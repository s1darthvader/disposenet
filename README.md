# DisposeNet: Hierarchical Debt Collection Call Classification

DisposeNet is an end-to-end machine learning pipeline designed to generate, train, evaluate, and deploy a custom NLP model for the Indian debt collection market. It categorizes call transcripts into a rigid, three-tier hierarchical taxonomy: **L1** (Contact Type), **L2** (Specific Disposition), and **L3** (Multi-label Interaction Flags).

Built on top of `ai4bharat/indic-bert`, DisposeNet natively handles Hindi, Hinglish, and English call transcripts using Roman script.

## 🚀 Key Features

*   **Synthetic Data Generation (Actor-Critic):** Utilizes LangChain and LangGraph to generate highly realistic, diarised call transcripts. It uses an LLM-as-a-judge feedback loop to ensure generated transcripts strictly adhere to disposition rules.
*   **Hierarchical Masking:** The PyTorch model (`DisposeNet`) features three separate linear classification heads. It enforces logical consistency during the forward pass by applying a penalty mask to L2 logits that are invalid based on the L1 prediction.
*   **Explainable AI (XAI):** Features an Integrated Gradients (InputXGradient) explainer that highlights the specific words in a transcript that contributed to (or suppressed) L2 and L3 predictions.
*   **Production API & Dashboard:** Includes a Flask REST API for batch inference and a vanilla HTML/JS dashboard for data visualization, distribution analysis, and confidence tracking.

## 🛠️ Usage Pipeline

### 1. Synthetic Data Generation
To generate new training data, open `collection_transcript_generator.ipynb`. This notebook uses Claude 3.5 Haiku (or Gemini 2.5 Flash) via LangGraph to generate realistic debt collection calls.
*   The pipeline auto-balances across Hindi, Hinglish, and English.
*   Outputs are saved as timestamped JSON files in the `inference_setup/overall-data/` directory.

### 2. Data Preparation & Training
Navigate to the `inference_setup/` directory. The training pipeline uses HuggingFace `Trainer` and PyTorch.

First, normalize the labels and generate the taxonomy mappings:
```bash
python prep2.py
```

Next, train the DisposeNet model. The script handles chunked tokenization (for long transcripts), dynamically masks invalid hierarchical paths, and trains the multi-head classifier.
```bash
python t2.py
```

### 3. Offline Evaluation & Explainability
Evaluate the trained model on the test set and generate HTML visualizations for model explainability (Integrated Gradients).
```bash
# Set EXPLAIN = True in infer.py to generate HTML heatmaps
python infer.py
```
*   Metrics (Macro F1, classification reports, confusion matrices) are saved to `infer_results.json`.
*   Visualizations are saved to the `explanations/` folder.

### 4. Deployment & Dashboard
There are two ways to run the dashboard depending on your needs.

**Option A: Production API (Real Inference)**
Runs the Flask application that loads the trained `.safetensors` model and performs actual inference.
```bash
cd inference_setup
python app.py
```
*   Access the UI at `http://localhost:8000`
*   API Endpoints: `POST /api/predict` and `POST /api/predict/explain`

**Option B: Development Mock Server**
If you are iterating on the frontend UI and don't want to load the heavy PyTorch model into memory, use the FastAPI mock server.
```bash
cd dashboard
uvicorn main:app --reload --port 8000
```

## 🧠 Model Architecture

The core architecture (`t2.py`) is built on `ai4bharat/indic-bert`.
1.  **Chunked Encoding:** Transcripts are split into chunks of 512 tokens, passed through the encoder, and max-pooled to handle long conversations without truncation.
2.  **Multi-Head Output:** The pooled embeddings feed into three separate dense layers (`l1_head`, `l2_head`, `l3_head`).
3.  **Composite Loss:** The model optimizes a combined loss function consisting of Weighted Cross-Entropy (L1), standard Cross-Entropy (L2), and Binary Cross-Entropy with Logits (L3).
